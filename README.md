# MikroTik AI Agent

Самостоятельно размещаемый сервис, который собирает конфигурации парка роутеров MikroTik,
версионирует их в git и позволяет спрашивать о них на естественном языке: «как настроен
файрвол на пограничном роутере», «через какие туннели ходит эта подсеть», «кто сейчас на
Wi-Fi и у кого слабый сигнал».

Только чтение. Изменять конфигурацию агент не умеет — ни через модель, ни иначе.

## Что делает

- **Собирает** `/export` с каждого устройства по SSH и коммитит в git — историю изменений
  и диффы получаете бесплатно.
- **Разбирает** конфиг детерминированным парсером: интерфейсы, VLAN, подсети, туннели,
  протоколы маршрутизации, счётчики правил.
- **Отвечает на вопросы** через LLM с вызовом инструментов: поиск по всем конфигам,
  выборка нужных секций, диффы, сводка по парку.
- **Читает живое состояние**: маршруты, ARP, DHCP-аренды, счётчики правил, клиенты Wi-Fi,
  handshake WireGuard — то, чего в сохранённом конфиге нет в принципе.
- **Считает расходы** на модель по каждому вызову API, с месячным лимитом.

## Безопасность

Сервис держит доступ ко всему парку, поэтому устроен так, чтобы навредить им было нельзя:

- На роутере заводится группа `mikrotik-agent-ro` с правами **`ssh,read`** — без `write`
  (нельзя изменить конфиг), без `sensitive` (роутер сам не отдаст секреты), без `test`
  (нельзя сгенерировать трафик).
- Команда, уходящая на роутер, **никогда не собирается из вывода модели**: модель передаёт
  ключ из белого списка, команда берётся из таблицы констант.
- Секреты вырезаются скраббером до отправки в модель; конфиги не сохраняются на стороне
  провайдера (`store: false`).
- Порт публикуется на `127.0.0.1` — сервис рассчитан на работу за обратным прокси.
- Все секреты в `/data` шифруются Fernet; ключ — `/data/master.key`.

Подробнее о том, почему сделано именно так, — [docs/DECISIONS.md](docs/DECISIONS.md).

## Быстрый старт

```bash
./deploy.sh
```

Интерфейс на http://127.0.0.1:8090 — при первом запуске попросит создать администратора.
Дальше: Настройки → API-ключ, затем добавить устройства и выполнить на каждом онбординг
(создаст read-only пользователя и зальёт ключ агента).

Развёртывание на сервер — [DEPLOY.md](DEPLOY.md).

## Разработка

Приложение запечено в образ, поэтому изменения кода требуют пересборки:

```bash
./deploy.sh                  # docker compose up -d --build с версией из git в шапке и /health
docker logs mikrotik-agent
```

Тесты запускаются внутри образа — локальный интерпретатор может быть старее, чем нужно:

```bash
docker run --rm -v "$PWD/tests:/app/tests" mikrotik-agent-mikrotik-agent python -m pytest tests -q
```

Заметки о поведении RouterOS, на которое напарывались, — [docs/ROUTEROS-NOTES.md](docs/ROUTEROS-NOTES.md).
Ориентиры по коду для ИИ-ассистентов — [CLAUDE.md](CLAUDE.md).
